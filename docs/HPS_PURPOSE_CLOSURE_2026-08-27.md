# HPS process-closure contract — 2026-08-27

Home, Profile, and Settings are not decorative secondary pages. They only earn permanent navigation if they close cross-surface jobs that Discover, Library, and Synthesis cannot own alone.

## Home — continuity authority
Home answers: **What deserves my attention or resumption now?**

Home must arbitrate across, in priority order where evidence supports it:
- explicit researcher decisions / approvals;
- failed or blocked work requiring recovery;
- active Synthesis constructions;
- active Discover acquisition / evidence work;
- recently touched Library evidence;
- newly completed durable outputs.

It must not default to a recent Library asset merely because one exists when a higher-consequence cross-surface task is active.

## Profile — research-context authority
Profile answers: **What does Research Drive currently believe about this researcher, and where does that context affect the system?**

Research memory is only allowed to claim downstream influence if that influence is real and testable. The page should expose identity, explicit editable user context, grounded registry context, research footprint, and visible downstream consumers.

No CTA may claim that research memory is editable unless a writable persistence contract exists.

## Settings — behavior/control authority
Settings answers: **How should this Research Drive installation behave, and what connections govern that behavior?**

A preference only belongs here if another surface actually reads it. Operational truth is allowed when it changes researcher decisions or access, but generic status duplication is not a reason for a setting.

## Acceptance
HPS is product-closed only when:
1. Home can resume meaningful work from all primary workflow surfaces rather than only Library/jobs.
2. Profile has a real editable research-context contract and shows its live consumers.
3. Discover/Ask/Synthesis consume the explicit research context where semantically appropriate.
4. Settings preferences are covered by consumer tests.
5. Cross-page tests prove the loops; visual QA alone is insufficient.
